# Miaomiao Search 前端设计说明

> 适用于 Next.js 门户实现；保留原静态原型的管理控制台风格。

## 1. 视觉主题与氛围

界面是“清晰、克制、可信”的浅色管理控制台：淡蓝灰工作区、白色内容面、蓝色操作色。它优先让搜索、配置和状态信息易于扫读，不使用营销页式大标题或装饰背景。

## 2. 色彩与角色

| Token | 值 | 用途 |
|---|---|---|
| `canvas` | `oklch(0.975 0.006 250)` | 页面背景 |
| `sidebar` | `oklch(0.955 0.012 250)` | 侧边栏与次级表面 |
| `surface` | `oklch(1 0 0)` | 卡片、表格、弹窗 |
| `ink` | `oklch(0.23 0.025 255)` | 主文字 |
| `muted` | `oklch(0.52 0.025 255)` | 辅助文字 |
| `accent` | `oklch(0.57 0.18 250)` | 主按钮、选中、链接 |
| `success` / `warn` / `danger` | `oklch(0.58 0.15 150)` / `oklch(0.72 0.16 75)` / `oklch(0.58 0.2 28)` | 状态反馈 |

## 3. 字体规则

为与历史原型一致，使用 `Plus Jakarta Sans` 作为界面字体、`JetBrains Mono` 作为数据与代码字体；二者由原型相同的 Google Fonts 地址加载。页面标题 24px/700/-0.012em，区块标题 14px/700，正文 13px/1.6，数据表与 Token 使用等宽数字。图标由与原型相同的 Phosphor Web CDN 加载。

## 4. 组件样式

- Button：8px 圆角，至少 40px 点击面积；主按钮使用 `accent`，按下缩放到 0.96。
- Input / SearchInput：8px 圆角、浅色填充、蓝色可见焦点环；错误时使用 `danger` 描边。
- Tag：胶囊形，仅用于引擎来源、状态和 Scope；引擎 Tag 必须通过共享 `EngineTag` 组件渲染官方 favicon + 名称，首页、结果、历史、引擎管理和统计页保持同一尺寸、间距和语义。
- Tabs：有语义的 `button`，底部短线和颜色表达选中状态。
- Card：12px 圆角，轻微阴影区分于画布；表格用分隔线而非层层卡片。
- Modal：用于需要集中查看或确认的内容；统一使用 16px 圆角并由外层容器裁切内容，保证四角视觉一致；关闭按钮统一放在右上角并保持足够点击面积，可通过关闭按钮和 Escape 关闭。

## 5. 布局原则

桌面端为 232px 左侧导航与可滚动主工作区；移动端导航切换为带圆角、边框和阴影的底部悬浮图标栏，内容区预留安全区；内容最大宽度 1024px。顶栏使用白底、项目标记、服务状态和登出操作，不展示语言选择区域；使用 4/8/12/16/24/32px 间距，不在数据页面插入横幅式介绍区域。

## 6. 层级与深度

画布、侧栏、卡片三层用亮度和 1–2 级轻阴影区分；卡片与表格边界使用半透明描边。圆角只使用 8px、12px、16px 和 pill 四档。

## 7. 约束

- 不使用渐变文字、玻璃模糊、厚色边栏或无意义插图。
- 不用 `transition: all`，只过渡颜色、透明度和变换。
- 不把模拟数据、模拟 Token 或模拟连接测试说成真实服务状态。
- 所有图标按钮提供 `aria-label`，状态颜色之外还必须有文字。
- 正文和日志只走 React 文本节点，不使用不安全 HTML 注入。

## 8. 响应式行为

小于 768px 时导航以悬浮胶囊固定在底部，仅显示五个图标入口，触摸目标至少 48px，并通过底部间距与安全区避免遮挡内容；小于 640px 时表格允许横向滚动、表单改为单列。使用 `prefers-reduced-motion` 降低动效。

## 9. 搜索首页结果布局

- 搜索首页采用“总览 + 引擎分组”的信息层级：顶部先给出聚合结果数、成功/失败引擎和历史入口，避免用户在长列表中寻找整体状态。
- 筛选区先用响应式三列网格承载引擎来源按钮，再将数量上限和 Bing 模式放在同一组配置行；每个来源按钮清楚表达选中、未选中和不可用状态。
- 结果区使用独立的结果工具条承载返回数量、耗时和“按引擎查看 / 聚合去重”切换；分组结果采用垂直堆叠卡片，卡片头部固定来源 Tag、返回数和状态，减少筛选控件与结果内容的视觉竞争。
- 结果区默认按引擎分组；每组标题显示来源、实际返回数/有效配置数和失败状态，不展示 `cache` 或 `snapshot` 标签。组内结果按序号、域名、标题、摘要排列，整条结果项可点击打开正文阅读器；B站结果改为视频详情弹窗，并通过 hover、focus-visible 和按下状态表达交互反馈。
- 使用紧凑的“按引擎查看 / 聚合去重”语义切换。聚合视图只合并 canonical URL，并通过来源 Tag 保留全部命中引擎。
- 加载、空结果、局部失败、全部失败和超时使用带图标与文字的状态面板，不能依赖颜色或手动模拟控件表达状态。
- 复用既有白色 Card、浅蓝工作区、引擎 Tag 和 Phosphor 图标；移动端按单列堆叠分组，所有操作保持可键盘聚焦。
- 结果项存在 `thumbnailUrl` 时，卡片右侧保留约 16:9 缩略图（桌面约 128×72，窄屏约 96×54）；使用原生 `img`、lazy loading 和 no-referrer，加载失败回到结果 favicon/地球图标。图片不改变标题、摘要和来源标签的文本层级，也不作为正文读取目标。
- Firecrawl、Tavily、GitHub、Bilibili 使用独立的浅色引擎 Tag 样式；凭据模式通过文字表达“需要 Key”“Token 可选”或“无需密钥”，不能只用颜色区分。可配置凭据的 Tag 明确显示可点击修改，弹窗提供官方申请入口和明文/脱敏切换。

## 10. Usage 统计审计页

- 统计页采用“时间范围 → KPI → 分布与趋势 → 引擎统计 → 审计日志”的分析顺序。范围选择器置于页面首屏顶部，默认最近 7 天，预设包含 24 小时、7 天、30 天、90 天，并提供自定义起止日期。
- KPI 卡片统一展示所选范围内的调用量、成功率、错误量、缓存命中率、平均延迟、P95 延迟和平均结果数；数字使用等宽数字并右对齐，避免把分页日志样本误读成总量。
- 趋势使用低噪声柱状图，Web 与 MCP 采用连续但可区分的蓝色层级；最近 24 小时按小时，其余范围按用户本地日期。Operation、Channel 和状态用轻量分布卡片，避免重复堆叠大卡片。
- 审计表格的筛选器与统计范围保持同一查询上下文，日志列优先展示时间、Channel、Operation、引擎、状态、耗时和结果数；分页控件放在表格底部，数字列右对齐。
- 审计页在 768px 以下保持单列阅读，筛选器可横向滚动，表格允许容器内滚动；底部悬浮图标导航的安全区不得被统计内容覆盖。

## 10. 登录页

- 登录页提供懒猫 OIDC 与本地账号两种入口，采用浅色画布、蓝色行星标记、左侧品牌说明与右侧登录面板的双栏布局；窄屏时只保留单栏登录面板。
- 视觉层级依靠留白、轻阴影和低对比度背景光晕建立，不使用彩色边框或营销式插画；主操作使用实心蓝色按钮，登录失败提示使用浅红背景和图标+文案。
- 两种登录表单使用同一分段控件；本地入口明确提示首次 OIDC 建号前不可用。中英文文案与 `html[lang]` 保持同步；表单支持键盘聚焦和 Enter 提交。

## 11. Settings 账户信息

- Settings 首屏以轻量白色卡片显示账号、显示名、角色和登录方式 Tag，登录方式使用“懒猫 OIDC / 本地账号”双语标签。
- 密码卡片与账户卡片并列，OIDC 会话隐藏当前密码输入并说明可直接设置；本地会话显示当前密码输入。成功和失败均通过既有 Toast 反馈。

## 12. 后续组件提示

- 创建 Settings 开关：卡片背景 `oklch(1 0 0)`，12px 圆角，文字 `oklch(0.23 0.025 255)`，选中轨道 `oklch(0.57 0.18 250)`。
- 创建状态 Tag：pill 圆角，12px/700，颜色同时搭配图标或状态文字。
- 创建搜索结果：紧凑分组列表而非瀑布式视觉卡片，标题 14px/700，URL 使用等宽 12px，来源使用 Tag。
