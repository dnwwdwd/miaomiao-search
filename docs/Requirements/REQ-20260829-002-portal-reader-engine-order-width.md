# REQ-20260829-002：正文阅读器、错误本地化、引擎顺序与桌面宽度

## 背景

搜索结果已经支持正文读取和多引擎返回，但正文弹窗在抓取期间缺少明确反馈，链接不可直接跳转；上游错误也会把 `UPSTREAM_UNAVAILABLE: Invalid URL`、Bing 302 和 CSDN Invalid URL 原样暴露给用户。引擎管理只能调整启停，首页与 MCP 的默认引擎顺序无法固定保存，桌面端内容区还受到过窄的最大宽度限制。

## 范围与验收

- 正文阅读器参考提供的文档弹窗布局，使用项目蓝色主题；标题下显示可点击的蓝色最终 URL，正文中的 HTTP(S) URL 以蓝色下划线链接渲染并在新窗口打开；左下角显示统一 `EngineTag` 来源标签。请求期间显示骨架屏，失败状态保留重试和打开源站操作。
- 前端按当前语言把引擎错误转换为友好摘要，默认隐藏原始错误；搜索失败横幅、结果分组、正文弹窗和引擎测试弹窗均可点击“查看详情”展开 `code: message`。MCP 响应不做本地化改写。
- 引擎管理提供“首页搜索顺序”和“MCP 搜索顺序”两个拖拽列表，并提供键盘可用的上下移动操作。顺序写入当前用户设置，刷新、再次搜索和 MCP 未指定 `engines` 时继续使用保存顺序；显式传入的引擎数组顺序保持不变。
- PC 门户内容容器使用视口约 90% 宽度；移动端继续使用全宽和底部导航安全区。

## 数据与安全边界

- 顺序保存为现有 `setting` 表中的 `search.homeEngineOrder` 和 `search.mcpEngineOrder` JSON 数组，不新增表或公开 MCP 字段。读取时过滤未知、重复和已移除引擎，并把新引擎追加到末尾。
- 正文链接只接受渲染为 HTTP(S) 新窗口链接，不根据正文链接发起二次抓取；正文仍以 React 文本节点渲染，不执行页面脚本。
- 本需求只改变门户显示文案，MCP 仍返回原始错误码和消息。

## 验收矩阵

| 场景 | 预期 |
|---|---|
| 点击搜索结果正文 | 弹窗先显示骨架屏，完成后显示标题、最终 URL、正文和来源引擎 Tag |
| 正文包含网页 URL | 链接为蓝色高亮，点击在新窗口打开 |
| `UPSTREAM_UNAVAILABLE`、Bing 302、CSDN Invalid URL | 中文/英文显示友好摘要；查看详情显示原始错误 |
| 拖拽首页或 MCP 列表 | 保存对应顺序，刷新后仍保持；两个列表互不影响 |
| MCP search 未传 engines | 使用 MCP 列表的保存顺序 |
| 桌面宽屏 | 页面主内容宽度约为视口 90%；窄屏布局不溢出 |
