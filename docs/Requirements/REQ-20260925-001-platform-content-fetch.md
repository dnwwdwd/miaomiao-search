# REQ-20260925-001 小红书与飞书内容抓取及飞书、知乎官方搜索

## 状态

实现完成，本地自动化验证通过；真实账号与懒猫设备验证待执行。关联决策：`DEC-20260925-001`。

## 范围

- 小红书按帖子链接抓取内容；不新增小红书搜索源。
- 飞书通过官方用户 OAuth 搜索当前用户可访问的文档，使用官方 API 读取；公开分享链接支持直接抓取，官方路径失败时回退分享页抓取。
- 知乎开放平台官方 CLI 提供站内搜索；Access Secret 按用户加密保存。
- 门户增加独立抓取页，按链接自动识别平台，提供预览、下载及懒猫文件拦截。
- MCP 新增按链接自动识别小红书与飞书的抓取 Tool；现有 `fetchWebContent` 遇到平台内容链接时也自动调用对应抓取器。
- 附加能力取直接服务于此流程的结构化元数据、正文结构和错误状态，见关联决策。

## 写入、读取与恢复

- 用户从抓取页提交 URL；搜索页和 MCP 搜索由知乎官方 CLI/飞书 Provider 提供候选。飞书官方搜索和读取使用当前用户授权令牌；公开分享链接可不经搜索直接抓取。抓取结果由预览读取，下载复用同一结果，避免正文不一致。
- MCP `fetchPlatformContent(url, maxChars?)` 返回结构化平台正文；`fetchWebContent` 按固定 HTTPS 主机与内容路径自动分流。两者读取当前 MCP Token 所属用户的飞书授权，受 Fetch scope、限流与审计约束。
- 结果只在页面状态和现有短时内存缓存保留；刷新后可重新抓取。新增抓取器或 Provider 版本变化时更换缓存键。
- 上游失败、登录要求、反爬和无正文显示对应错误及源站入口；重试由用户发起。不建立本地归档与永久保存。

## 安全与兼容

- 校验输入与跳转的协议、凭据、主机、长度和资源大小；只对识别出的平台使用专用抓取器。
- 保留当前用户认证、速率限制、审计和结果长度边界；预览不执行源站 HTML、脚本，不暴露 Cookie 或 Token。
- 飞书 App Secret 与用户 Token 仅保存于当前用户加密设置；用户授权和懒猫登录独立，注销飞书授权不影响门户登录。
- 保留其它引擎配置、历史与 MCP Token；移除旧 `zhihu` 引擎配置及其 Cookie 设置，保留 `zhihu_official`；飞书新引擎的默认状态按决策落实。
- 外部索引、权限、反爬和页面结构可能导致无结果；不得把空壳页面伪装为成功。

## 行为验收矩阵

| 场景 | 验收 |
|---|---|
| 小红书有效分享链接 | 识别帖子，展示正文和可用元数据；不调用搜索 |
| 小红书缺 Token / 反爬 | 明确错误及源站入口，不展示伪内容 |
| 飞书公开 wiki/docx/docs | 自动选择官方读取或分享页抓取，官方路径无法读取时回退分享链接；保留标题、列表、代码块并识别截断 |
| 飞书私有链接 | 显示无权限/需登录，不保存登录页 |
| 飞书关键词搜索 | OAuth 后用官方搜索 API 返回当前授权用户可访问的文档/Wiki；未授权显示连接入口 |
| 飞书 OAuth | 当前用户配置 App ID/Secret，完成设备授权，令牌自动刷新；不同门户用户凭据隔离 |
| 知乎官方 CLI 搜索 | 独立启用，要求当前用户的 Access Secret；调用官方 `search zhihu`，单次最多 10 条；结果展示摘要详情并可打开源站；频率及额度错误显示本地化摘要，详情不含 CLI 原始输出 |
| 门户预览/下载 | 平台识别、中英文文案、HTML `lang`、窄屏与 Blob 下载正常 |
| MCP 平台抓取 | `fetchPlatformContent` 输入任一受支持平台 URL 后自动返回对应平台与 Markdown；`fetchWebContent` 对同类 URL 自动分流，普通 URL 保持通用结果 |
| MCP 权限与隔离 | Search-only Token 无权抓取；调用按 Token 所属用户读取凭据并记录 MCP 审计 |
| 懒猫设备下载 | 官方脚本接管 Blob 下载；本地浏览器保留普通下载 |
| 恶意 URL/跳转 | 非 HTTP(S)、带凭据、伪装主机、跨平台跳转和超大响应被拒绝 |
