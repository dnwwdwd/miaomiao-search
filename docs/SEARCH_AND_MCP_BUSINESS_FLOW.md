# 搜索与 MCP 业务流程

> 最后更新：2026-08-23
> 状态：设计基线，尚未实现
> 适用范围：Web Search、Remote MCP、认证、缓存、审计和正文抓取

## 入口与前置条件

- Web 入口：管理员在 Login 页面登录，浏览器通过 HttpOnly JWT Cookie 访问受保护的 `/api/*`。
- MCP 入口：外部 Agent 向 `/mcp` 发送 Streamable HTTP 请求，并在 Authorization Header 中提供有效 Bearer Token。
- 前置数据：管理员账户、引擎配置、系统设置和 Access Token 由 SQLite 持久化；搜索与正文缓存为进程内缓存。
- 非目标范围：V1 不向普通终端用户开放多账户权限；不加入 Playwright 搜索模式，Bing 的实际执行路径固定为 HTTP request。

## Web 搜索主流程

1. 管理员输入关键词或完整 URL；空输入不能提交。
2. 输入完整 URL 时，前端提供正文读取入口；关键词搜索时提交引擎、数量和适用的 Bing 搜索模式。
3. 服务端校验管理员会话和参数，读取引擎配置与缓存。搜索请求按引擎并发执行，合并同 URL 的来源并保留部分失败信息。
4. 服务端写入搜索历史与请求日志；历史默认不保存网页正文。
5. 前端展示结果、来源标签、部分失败或明确错误状态。正文请求需逐项检查 URL、DNS 结果与重定向，再提取并安全呈现内容。

## MCP 主流程

1. 客户端通过 `/mcp` 发起 Streamable HTTP 请求。
2. 服务端检查 Authorization Header、Token Hash、状态、过期时间、Scope 和限额。
3. 已授权请求调用 `search` 或正文 Tool；搜索与 Web 共享可用缓存，站点专用 fetch Tool 遵从管理员启停状态。
4. 服务端记录 Token 最近使用时间、当天调用量和请求审计信息，再按 MCP 语义返回结果。

## 状态、异常与安全边界

| 场景 | 系统行为 | 用户或客户端反馈 | 可恢复方式 |
|---|---|---|---|
| 单个搜索源失败 | 保留其他成功结果并记录失败原因 | Web 显示部分失败横幅；MCP 返回兼容结果与失败信息 | 更换或减少引擎，稍后重试。 |
| 所有搜索源失败 | 不返回伪结果，记录错误 | 区分超时、限流、代理和运行时失败 | 检查网络、代理、引擎状态或运行时配置。 |
| 危险正文 URL | 在请求和每次跳转时拒绝 | 返回明确 SSRF 错误 | 使用可访问的公网 HTTP(S) URL。 |
| MCP Token 无效或超限 | 拒绝 Tool 调用并审计 | 401、403 或限流错误 | 使用有效 Token，等待限流窗口或调整额度。 |
| Token Secret 丢失 | 数据库中不能恢复原文 | 创建时只展示一次 | 创建新 Token，并按需要撤销旧 Token。 |
