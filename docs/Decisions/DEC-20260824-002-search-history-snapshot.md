# DEC-20260824-002 搜索历史结果快照

## 状态

已确认并实施。用户要求历史记录同时保留关键词、所选引擎与当次搜索结果，并支持查看快照及再次搜索。

## 方案

- 在 `search_history` 增加可空的 `result_snapshot` JSON 文本列，保持对已有历史记录的兼容。
- Web 搜索成功或部分成功后，由 `SearchService` 写入去重后的结果与引擎失败信息；MCP 调用和引擎健康测试不写入 Web 历史。
- `/api/history` 返回快照；旧记录或损坏快照返回 `null`，前端展示无快照状态并允许再次搜索。
- 前端历史弹窗分为记录列表与详情视图，详情显示结果快照、失败引擎、原始选择，并提供“再次搜索”获取最新结果。

## 边界

- 快照只保存搜索返回的标题、URL、摘要、引擎和失败信息，不保存正文抓取内容、Token 或认证信息。
- 现有历史保留天数和清空入口继续作用于快照记录。
- 未来若结果体积明显增长，再单独评估压缩、分页或独立结果表，不在本次范围内引入复杂 schema。

## 验收

1. 新搜索后，历史 API 同时返回关键词、引擎、结果数量和结果快照。
2. 点击历史记录能看到保存的结果；无快照的旧记录有明确空状态。
3. 点击“再次搜索”使用保存的关键词和仍启用的引擎请求最新结果。
4. 旧数据库启动时自动执行增量迁移，不丢失已有历史。
