# DEC-20260928-001 内容抓取按链接匹配现有抓取器

## 状态

按用户对内容抓取页自动匹配、未支持链接走通用网页抓取和统一来源标签颜色的要求实施；本地代码完成，补充改动待回归。

## 方案

在现有 `/api/fetch-content` 请求体增加可选 `autoMatch`，默认关闭，只由内容抓取页传入。服务端识别受支持的平台和专用站点，调用既有抓取器；没有命中专用来源与路径的 URL 走通用网页抓取。自动匹配关闭时的调用语义保持原样。响应增加可选站点来源字段，用于预览标签。平台抓取继续返回媒体元数据。

仅 HTTPS 且主机、内容路径均准确匹配时才使用专用抓取器。Linux.do 的普通主题地址转换为上游要求的 `/t/topic/<id>.json`；GitHub 仅仓库首页匹配 README 抓取器。站点专用抓取器目前主要返回文本，正文预览和 Markdown 文件保留这些文本；不推断不存在的图片链接。

内容抓取页的来源标签复用首页 `EngineTag` 组件和来源色板，并保留当前语言对应的名称。现有 `/api/platform-content`、MCP Tool、搜索页阅读器及默认 `/api/fetch-content` 调用语义保持不变。鉴权、限流、审计、URL 约束及用户隔离沿用当前服务。
