# 懒猫微服移植与打包指南

本文用于指导 AI Agent 在 `/home/burger/Documents/lzc-projects` 下移植 Web 应用到懒猫微服，并生成可安装的 LPK 包。

项目子目录若有自己的 `AGENTS.md`，先按项目级说明执行；本文件只补充通用移植口径。

---

## 1. 移植前先看什么

开始写 `package.yml`、`lzc-manifest.yml` 或 `lzc-build.yml` 前，先确认项目真实情况：

```bash
git remote -v
cat package.json 2>/dev/null
cat pyproject.toml 2>/dev/null
cat pom.xml 2>/dev/null
cat Cargo.toml 2>/dev/null
cat go.mod 2>/dev/null
find . -maxdepth 2 -name 'docker-compose*.yml' -o -name 'compose*.yaml'
find . -maxdepth 2 -name AGENTS.md -print
```

需要判断：

- 应用是否已经在懒猫商店上架；已满足需求时，优先建议直接安装。
- 上游作者是谁。以 `git remote -v` 的仓库 owner 为准，不用 `git log` 的提交作者。
- 项目是否是 Web 应用；CLI、桌面应用要先评估 Web 化成本。
- 是否兼容 Linux amd64。
- 是否已有 `package.yml`、`lzc-manifest.yml`、`lzc-build.yml`。
- 当前是 LPK V1 旧布局，还是 LPK V2 元数据分离布局。
- 是否需要登录、OIDC、文件导入、文件导出、持久化目录、后台任务、长连接。
- 是否依赖 PostgreSQL、MySQL、Redis、RabbitMQ、Kafka、Elasticsearch、Selenium、Playwright 等重组件。

重组件和浏览器自动化会增加镜像体积、启动耗时和健康检查风险，先把代价说清楚再动手。

---

## 2. 基本红线

1. `buildscript` 和它调用的脚本不得执行 `lzc-cli project build`，避免递归构建。
2. 正式发布镜像必须来自 `registry.lazycat.cloud`。
3. 新项目默认使用 LPK V2，并在 `package.yml` 里声明 `min_os_version: "1.5.0"`。
4. `author` 必须来自 `git remote -v` 的仓库 owner；`homepage` 和 `license` 来自上游仓库或项目元数据。缺失时询问用户。
5. `package`、`version`、`author` 在相关文件里保持一致。
6. `locales` 默认包含 `zh`、`zh_CN`、`en`、`ja`，每项都有 `name` 和 `description`。
7. 运行时不得写入 `/lzcapp/pkg/content/`。
8. 可变数据写到 `/lzcapp/var/`，缓存写到 `/lzcapp/cache/`。
9. 无明确需求时，不接管 `80/443`，不额外暴露系统端口。
10. OIDC 只在原项目已有登录体系、用户明确要求，或项目级文档要求时接入。
11. 不要用 inject 模拟登录流程。
12. 普通附件选择入口不要设置 `accept="*/*"`。
13. 纯前端静态项目默认暂停移植，除非用户明确要求继续。

## 3. 推荐文件结构

新移植项目默认整理为：

```text
.
├── package.yml
├── lzc-manifest.yml
├── lzc-build.yml
├── lzc-icon.png
├── lzc/
│   ├── build-package.sh
│   ├── run.sh
│   └── lazycat-injects/
│       └── lzc-file-chooser-inject.js
└── lzc-dist/
```

`lzc-build.yml` 常用写法：

```yaml
buildscript: sh lzc/build-package.sh
manifest: ./lzc-manifest.yml
contentdir: ./lzc-dist
pkgout: ./
icon: ./lzc-icon.png
```

构建脚本负责清理 `lzc-dist`、构建前端、准备依赖、复制运行脚本和静态资源。运行脚本只启动服务，不做 `npm install`、`pip install`、前端 build 这类重操作。

## 4. package.yml 写法

LPK V2 中，`package.yml` 放静态元数据和权限。

```yaml
package: cloud.lazycat.app.your-app
version: 0.1.0
name: Your App
description: One-line description of what the app does.
author: <真实作者>
homepage: <真实 URL>
license: <真实许可证>
min_os_version: "1.5.0"

locales:
  zh:
    name: "Your App"
    description: "一句话说明应用真实能力"
  zh_CN:
    name: "Your App"
    description: "一句话说明应用真实能力"
  en:
    name: "Your App"
    description: "One-line description of what the app does"
  ja:
    name: "Your App"
    description: "アプリの実際の機能を表す1行説明"

permissions:
  required:
    - net.internet
```

常用权限：

- `net.internet`：访问互联网。
- `net.lan`：访问局域网。
- `document.private`：使用 `/lzcapp/documents/$uid`。
- `document.read` / `document.write`：访问公共文稿。
- `media.read` / `media.write`：访问媒体目录。
- `device.dri.render`：访问 GPU。

新项目优先用 `permissions`。旧项目里的 `ext_config.enable_document_access` 只做兼容维护。

作者字段按 remote owner 填。例如：

```text
origin  https://github.com/XxSnake/project-management-system (fetch)
```

对应：

```yaml
author: XxSnake
homepage: https://github.com/XxSnake/project-management-system
```

不要从 `git log` 里挑提交作者填 `author`。

## 5. lzc-manifest.yml 写法

LPK V2 中，`lzc-manifest.yml` 只放运行结构，不放 `package`、`version`、`locales`、`permissions`。

单服务：

```yaml
application:
  subdomain: your-app
  routes:
    - /=http://web.cloud.lazycat.app.your-app.lzcapp:8080

services:
  web:
    image: registry.lazycat.cloud/<namespace>/<image>:<tag>
    command: sh /lzcapp/pkg/content/lzc/run.sh
    binds:
      - /lzcapp/var/data:/lzcapp/var/data
```

前后端拆分：

```yaml
application:
  subdomain: your-app
  routes:
    - /=http://web.cloud.lazycat.app.your-app.lzcapp:8080
  upstreams:
    - location: /api/
      backend: http://api.cloud.lazycat.app.your-app.lzcapp:9000
      disable_trim_location: true

services:
  web:
    image: registry.lazycat.cloud/<namespace>/<image>:<tag>
    command: sh /lzcapp/pkg/content/lzc/run-web.sh
  api:
    image: registry.lazycat.cloud/<namespace>/<image>:<tag>
    command: sh /lzcapp/pkg/content/lzc/run-api.sh
    binds:
      - /lzcapp/var/data:/lzcapp/var/data
```

服务间访问使用：

```text
http://{service}.{package}.lzcapp:{port}
```

跨服务调用不要写死 `127.0.0.1`。同一容器内多个进程可以用 localhost，但要写清楚。

## 6. 路由选择

`routes` 适合简单 HTTP 转发，默认会裁掉匹配前缀。

```yaml
application:
  routes:
    - /=http://web.cloud.lazycat.app.demo.lzcapp:8080
```

需要保留路径前缀、处理 Host 校验、多域名分流或清理请求头时，用 `upstreams`。

```yaml
application:
  upstreams:
    - location: /api/
      backend: http://api.cloud.lazycat.app.demo.lzcapp:9000
      disable_trim_location: true
      use_backend_host: true
```

TCP/UDP 用 `ingress`，不要塞进 `routes`：

```yaml
application:
  ingress:
    - protocol: tcp
      port: 3306
      service: mysql
```

`ingress` 只做网络转发，不提供应用层鉴权。需要复杂 Nginx 行为时，再考虑 `app-proxy`。

## 7. 镜像与体积

正式发布镜像使用 `registry.lazycat.cloud`。不要猜 tag，先查已有项目或 `lzc-cli appstore my-images`。

### Node / Python 基座优先级

打包 Node 或 Python 应用时，优先复用下列 `library` 基座，在 LPK 中放入应用代码、已安装依赖、构建产物和启动脚本。不要为了预装应用依赖就新建并发布 `registry.lazycat.cloud/<namespace>/<app>-lazycat...` 这类自定义应用镜像。

当前目录的源 `lzc-manifest.yml` 中，以下两组使用最广，作为新项目的默认选择：

| 运行时 | 默认镜像 | 清单服务引用数 |
| --- | --- | --- |
| Node Web / SSR | `registry.lazycat.cloud/u30387910/library/node:549f023f95a10c59` | 27 |
| Python Web / API | `registry.lazycat.cloud/u30387910/library/python:e44876804abb84a0` | 14 |

目录内已经使用过的其他 Node / Python tag 如下。仅当默认基座经实际构建验证无法满足运行时、原生依赖或系统库要求时，才从这里选择与相似项目一致的 tag；仍需完成构建和启动验证。

| 运行时 | 已验证 tag |
| --- | --- |
| Node | `00874b2e95c32de7`、`098574bb9b92a59e`、`75be1ac8935eb941`、`97cd11f6df6990e9`、`b58b553926e84e8f`、`c4a7c9aa63818016`、`e6ae6c222296b29f` |
| Python | `5b0a0703114db151`、`625840f259e78399`、`ad70f82995ca8ca2`、`b0ea851a3b37269c`、`e88b9806d02d59ac`、`fcd94252db284c1b`、`fea90efa2367152a` |

自定义应用镜像只能用于现成 Node/Python 基座无法承载的明确场景，例如必须由镜像提供且不能在 LPK 构建阶段准备的系统级运行时。采用前要在项目说明中写明缺少的能力、为什么不能复用基础镜像，以及验证结果。

常用的非 Node/Python 基座：

| 场景 | 镜像 |
| --- | --- |
| Debian | `registry.lazycat.cloud/u30387910/library/debian:cb352a5223b8abc9` |

本指南不使用 `embed:` 或 `lzc-build.yml images:` 的内嵌镜像打包方式。LPK 里只保留清单、图标、注入脚本和必须从包内加载的静态内容。

## 8. 存储路径

运行时路径按用途放：

- 持久化数据：`/lzcapp/var/data`
- 配置文件：`/lzcapp/var/config`
- 缓存和临时文件：`/lzcapp/cache`
- 私有文稿：`/lzcapp/documents/$uid`
- 包内容：`/lzcapp/pkg/content`，只读

默认配置可以从包内复制到可写目录：

```yaml
services:
  app:
    binds:
      - /lzcapp/var/config:/app/config
    setup_script: |
      if [ ! -f /app/config/config.yml ]; then
        cp /lzcapp/pkg/content/default-config.yml /app/config/config.yml
      fi
```

不要把代码副本、构建产物、运行时依赖放进 `/lzcapp/var`。升级时包内容会更新，持久化目录只保存用户数据和配置。

## 9. 文件选择器与下载保存拦截

需要插入文件、插入图片、导出文件，或支持懒猫网盘「用当前应用打开」时，接入官方 chooser。

manifest 示例：

```yaml
application:
  injects:
    - id: lazycat-file-chooser
      on: browser
      when: ["/*"]
      do:
        - src: file:///lzcapp/pkg/content/lzc/lazycat-injects/lzc-file-chooser-inject.js
          params:
            diskRoot: /_lzc/files/home
            fallbackMime: application/octet-stream
            locale: auto
            hooks:
              fileSystemAccess: true
              fileInput: true
              download: true
              objectUrl: true
  file_handler:
    actions:
      open: /?fileUrl=/%u
```

下面四个 hooks 要显式打开：

- `fileInput` 接管 `<input type="file">`。
- `fileSystemAccess` 接管 `showOpenFilePicker()` 和 `showSaveFilePicker()`。
- `objectUrl` 跟踪 `URL.createObjectURL(blob)`。
- `download` 接管 `<a download href="blob:...">.click()`。

打包脚本必须把官方脚本放进 LPK：

```sh
mkdir -p "$DIST_ROOT/lzc"
cp -R "$REPO_ROOT/lzc/lazycat-injects" "$DIST_ROOT/lzc/lazycat-injects"
```

### 插入文件和图片

- 普通附件使用原生 `<input type="file">`，不设置 `accept`。
- 图片入口设置 `accept="image/*"`。
- 不要设置 `accept="*/*"`，否则 picker 可能只显示目录。
- 前端只接收浏览器 `File` 对象，本地文件和懒猫文件复用同一套上传链路。

### 用当前应用打开

`file_handler` 只处理文本和代码类单文件。文件 URL 必须同源，并位于 `/_lzc/files/home/...` 下。上传成功后插入 `@uploads/...`，再清理地址栏里的 `fileUrl`。

### 导出和保存到懒猫

后端导出接口返回真实文件响应：

- `Content-Type` 准确。
- `Content-Disposition: attachment; filename="..."` 或 `filename*=UTF-8''...`。
- Excel、Markdown、PDF、数据库备份等都走文件响应。

前端下载必须改成二进制流链路：

```ts
async function downloadFile(url: string, filename: string) {
  const res = await fetch(url)
  if (!res.ok) throw new Error("Download failed")

  const blob = await res.blob()
  const blobUrl = URL.createObjectURL(blob)
  const anchor = document.createElement("a")
  anchor.href = blobUrl
  anchor.download = filename
  document.body.appendChild(anchor)
  anchor.click()
  anchor.remove()
  window.setTimeout(() => URL.revokeObjectURL(blobUrl), 60_000)
}
```

下面几种写法不要作为主下载链路：

- `window.open("/api/.../download")`
- `location.href = "/api/.../download"`
- 直接 `<a href="/api/.../download">`
- 在 `anchor.click()` 前执行 `URL.revokeObjectURL(blobUrl)`

如果下载接口和页面存在跨域，先解决 CORS，让前端能 `fetch()` 到二进制内容。无法 `fetch()` 成 Blob 的下载，官方脚本通常拦不到懒猫保存入口。

保存到懒猫会打开文件应用 iframe。后端或反代设置了 CSP 时，需要允许懒猫文件域名：

```text
Content-Security-Policy:
  default-src 'self';
  img-src 'self' data: https:;
  style-src 'self' 'unsafe-inline';
  script-src 'self';
  connect-src 'self' https:;
  frame-src 'self' https://*.heiyu.space;
```

`frame-src` 缺失时，浏览器会拦截 `https://file.<box>.heiyu.space/`，用户看不到保存到懒猫的文件选择器。不要用 `default-src *` 处理这个问题。

官方注入脚本升级时整文件替换，不在官方脚本上直接打本地补丁。

## 10. OIDC

只有原项目已有登录体系、用户要求接入，或项目级文档要求时，才加 OIDC。

```yaml
application:
  oidc_redirect_path: /auth/oidc.callback
```

服务里传入环境变量：

```yaml
services:
  app:
    environment:
      - OIDC_CLIENT_ID=${LAZYCAT_AUTH_OIDC_CLIENT_ID}
      - OIDC_CLIENT_SECRET=${LAZYCAT_AUTH_OIDC_CLIENT_SECRET}
      - OIDC_ISSUER_URI=${LAZYCAT_AUTH_OIDC_ISSUER_URI}
      - OIDC_AUTH_URI=${LAZYCAT_AUTH_OIDC_AUTH_URI}
      - OIDC_TOKEN_URI=${LAZYCAT_AUTH_OIDC_TOKEN_URI}
      - OIDC_USERINFO_URI=${LAZYCAT_AUTH_OIDC_USERINFO_URI}
```

如果保留本地登录入口，用 `public_path` 放行登录页、回调页和必要认证接口，不要放行核心业务 API。

```yaml
application:
  public_path:
    - /login
    - /api/auth/*
```

## 11. 构建与验证

按项目技术栈选择命令：

```bash
sh lzc/build-package.sh
lzc-cli project build
lzc-cli project deploy
npm run build
pnpm build
python -m compileall .
pytest
cargo check
go test ./...
```

LPK 检查项：

- `package.yml`、`lzc-manifest.yml`、`lzc-build.yml`、`lzc-icon.png` 存在。
- `lzc/build-package.sh` 存在并能生成 `lzc-dist`。
- `package`、`version`、`author` 一致。
- `locales` 完整。
- 正式镜像来自 `registry.lazycat.cloud`。
- 运行时不写 `/lzcapp/pkg/content`。
- 有健康接口时配置 `healthcheck`。
- 使用文件选择器时，注入脚本已打进 LPK。

命令失败时，记录失败命令、错误摘要和未验证范围。

## 12. 常见故障

| 现象 | 常见原因 | 处理方式 |
| --- | --- | --- |
| `Read-only file system` | 写入 `/lzcapp/pkg/content` | 改到 `/lzcapp/var` 或 `/lzcapp/cache` |
| 健康检查循环失败 | 启动阶段安装依赖或初始化过重 | 把依赖安装前移到打包阶段 |
| picker 只显示目录 | 普通附件 input 设置了 `accept="*/*"` | 移除普通附件入口的 `accept` |
| 升级后代码没生效 | 代码或产物放进持久化目录 | 代码随包或镜像发布 |
| Host 或跨域错误 | 后端校验 Host 或 Origin | 用 `upstreams` 配 `use_backend_host` 或移除特定请求头 |
| 权限不足 | 容器用户无法写持久化目录 | 以 root 运行，或用 `setup_script` 修目录权限 |
