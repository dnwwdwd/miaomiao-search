# Miaomiao Search UI Guide

## Usage 审计页布局补充

- 统计审计页以服务端 `GET /api/usage` 的选定时间范围为唯一统计口径，默认最近 7 天，并支持最近 24 小时、7 天、30 天、90 天和自定义起止时间。
- 顶部范围控制与 Web/MCP、Operation、状态、引擎筛选共用一套查询条件；总调用量、成功/部分成功/错误、成功率、缓存命中率、平均延迟、P95 延迟、平均结果数、趋势和引擎统计必须同步更新。
- 趋势按用户时区按日分桶，最近 24 小时按小时分桶；审计日志使用服务端筛选和分页，页面不再使用“最近样本”或“Top 100”口径。无数据时明确显示当前选定时间范围。

> 最后更新：2026-08-25
> 当前依据：`喵喵搜索 PRD.md`、`docs/DESIGN.md` 与 Next.js 门户源码。`miaomiao_search_portal.html` 保留为历史交互原型，Next.js 门户按其应用框架和信息组织还原，并接入本地服务。

## 全局规则

- 登录后采用原型中的顶栏加导航的管理控制台布局。桌面端侧栏宽 240px，包含联网搜索、MCP 服务、引擎管理、统计审计、系统配置；移动端改为带圆角、边框和阴影的悬浮图标导航，不显示菜单名称，当前页面使用蓝色背景和图标高亮。
- 顶栏展示应用名（喵喵搜索 / Miaomiao Search）、中文/英文切换和登出操作。登出通过管理 API 清除应用会话后回到门户根路径，由未登录状态显示登录页；本地账号数据保留。中英文切换属于 V1 范围；新增页面文案应同时维护两种语言。
- 网站 favicon 使用 `app/icon.svg`，与顶栏蓝色渐变行星品牌图标保持同一视觉语言。
- Next.js 门户使用浅色背景、蓝色主操作、卡片式内容区和状态徽标。基础组件位于 `src/components/ui/`，包括 Button、Input、SearchInput、Tag、Tabs、Switch、RadioGroup、Dropdown、Select（兼容层）、Modal、Toast。
- 页面统一使用 `RadioGroup` 处理单选状态、`Dropdown` 处理下拉选择；下拉组件支持键盘方向键/Home/End、Enter/Space、Esc 和点击外部关闭，并暴露 listbox/option 语义。
- `Modal` 统一通过 Portal 渲染，锁定背景滚动，支持 Esc/遮罩关闭、焦点回收与 Tab 焦点循环；登录和搜索表单都应支持 Enter 提交。小于 768px 时导航以悬浮胶囊形式移到底部并仅显示图标，内容区预留底部安全区；搜索表单自动换行，宽表格保留容器内横向滚动，并使用统一的可见、可拖拽滚动条样式。
- 顶部菜单统一展示本地服务状态 Tag（连接中、服务在线、服务离线），页面内容不再重复放置 Live/Active 服务状态；品牌名称按语言显示为“喵喵搜索 / Miaomiao Search”，不展示项目版本说明。
- 页面级标题说明默认压缩为一句话；MCP 客户端配置模板保留 JSON 换行、长行自动折行，并支持容器内滚动查看。

## 页面与关键状态

### Login

- 组件：懒猫 OIDC/本地账号分段切换、OIDC 登录按钮、本地账号密码表单和通用错误提示。
- 本地账号表单提示用户先完成一次懒猫 OIDC 登录；页面不得根据 `X-HC-*` 头自动进入门户。失败提示使用中英文通用文案，不能显示 OIDC 上游错误详情。
- 登录页采用浅色留白、蓝色行星品牌标记和双栏登录面板；移动端收为单栏。登录页不使用彩色边框，保留轻量阴影、背景光晕和明确的焦点/按下反馈。

### Search

- 搜索历史弹窗保留关键词、所选引擎和当次结果快照；点击记录在同一弹窗内进入详情，详情页顶部提供放大的“返回历史”按钮、时间和快照数量，结果序号位于每条结果卡片右上角且不使用序号边框，并恢复之前的列表滚动位置，也可点击底部“再次搜索”获取最新结果。历史列表页的“清空历史”位于左下角，“关闭”位于右下角；旧记录没有快照时显示空状态，不影响重新搜索。
- 组件：搜索输入、URL 正文读取提示、引擎多选、恢复默认、结果数量、Bing 高级选项、结果列表、部分失败横幅、正文阅读、搜索历史。
- 首页搜索引擎来源使用响应式网格按钮，官方 favicon 与引擎名称作为整体水平居中，选中状态固定在按钮右侧；结果卡片、历史记录、引擎管理、统计页也复用同一套标签样式。DuckDuckGo 图标使用仓库内静态资源，避免依赖外链 favicon。
- 结果条目展示标题、URL、域名、描述和来源引擎；首页结果与历史快照结果整条可点击打开正文阅读器，使用 hover、focus 和按下反馈提示可交互，不再放置单独的“读取网页正文”按钮。正文阅读器内保留“打开源站”操作；聚合视图保留多个来源标签，避免去重后丢失来源信息。
- 多引擎结果需求 `REQ-20260824-007` 已实现：默认按引擎分组，每组显示实际/有效配置数量、加载、空结果和失败状态；结果区不展示 `cache` 或 `snapshot` 标签，可切换聚合去重视图，平铺 `results` 保持兼容。
- 搜索结果 JSON 查看器采用浅色工作台外壳和深色代码面板，显示查询、聚合数量、引擎数和 JSON 字符数；底部提供一键复制、复制状态反馈和关闭操作，窄屏允许代码区独立滚动。
- 首页默认“使用引擎默认值”，可选 5 / 10 / 20 / 30 / 50 作为每个引擎本次上限；首页上限和 Bing 模式会通过设置接口持久化，但不覆盖引擎管理页的独立数量，也不限制聚合总数。引擎管理页通过内联下拉设置每个引擎的独立数量，未单独配置时使用搜索默认值 10。
- 需要配置凭据的引擎只能在服务端检查通过后启用：Exa 需要已保存 API Key。DuckDuckGo 保留“需要代理”标记，启用时提示用户确认懒猫微服 VPN/TUN 已开启，不依赖 Settings 开关。Exa 的 API Key 通过引擎管理页弹窗配置，保存后提示重启独立运行的 Open-WebSearch daemon，页面和接口响应不回显密钥。
- 正文阅读展示标题、原始 URL、最终 URL 和正文；正文区域使用蓝色边框，抓取期间由铺满阅读区的骨架屏承载等待状态，不额外显示加载提示。提供复制正文与打开源站。页面已访问但未识别到正文时，不显示笼统的 400 错误，而是说明可能依赖 JavaScript 或未暴露正文，并提供重试和打开源站。
- 加载、空结果、部分引擎失败、全部失败和超时均由实际 API 响应显示；首页默认按引擎分组，并可切换到聚合去重视图，不保留手动伪造状态控件。
- 正文阅读器参考文档弹窗的宽屏布局，使用项目蓝色主题；抓取期间显示骨架屏，标题下的最终 URL 与正文中的 HTTP(S) URL 使用蓝色高亮并在新窗口打开，底部左侧显示统一搜索引擎 Tag。正文和搜索错误默认展示当前语言的友好摘要，点击“查看详情”才展开原始错误码与消息。
- 引擎管理提供首页搜索顺序和 MCP 搜索顺序两个可拖拽列表，并提供上下移动按钮；顺序写入用户设置，刷新后继续生效，禁用引擎重新启用后保留原位置。桌面门户主内容宽度约为视口 90%，移动端保持全宽。

### MCP

- 组件：Endpoint、Tool 列表、Token 列表、新建 Token、客户端配置模板、管理 API 检查。传输协议不在门户中重复展示，协议事实以服务端 Endpoint 与客户端配置模板为准；该检查读取实际管理端元数据与 Tool 声明，不替代带 Token 的 MCP initialize 调用。`search` Tool 的引擎 schema 在每次 MCP 请求建立时读取当前引擎管理启用状态。
- Token 创建表单的每分钟限流和每日调用上限分别支持“无限制”或手动输入；手动值必须符合服务端范围。创建后完整 Secret 只展示一次，弹窗提供一键复制和复制失败提示；列表显示名称、Prefix、Scope、配额、过期时间、最近使用时间、UTC 当日真实调用量和状态。每行支持启用/禁用、撤销和删除；删除必须经过确认，已有审计记录保留。

### Engines、Usage 与 Settings

- Usage：显示 Web/MCP 调用量、成功率、缓存命中率、平均响应时间、引擎统计和包含 PRD 字段的请求日志。
- Usage KPI 卡片在桌面端最多四列排列，审计日志的筛选器、表格和分页共用横向滚动容器，滚动条位于审计卡片底部；窄屏继续保留容器内横向滚动。
- Engines：显示名称、官方图标、启用、默认、Search Mode、每次返回数量、启用前置条件、最近测试时间、状态、延迟、最近错误；Exa 提供 API Key 配置弹窗，密钥只写入加密设置。
- Settings：顶部显示当前账号、角色和“懒猫 OIDC / 本地账号”登录方式；密码卡片按会话类型显示改密提示和表单。其他设置包括搜索/正文缓存、限流、默认引擎与数量、搜索历史和 MCP Query 日志；搜索历史保留天数支持“永久保存”。懒猫微服部署不要求填写代理地址；本地开发 daemon 如需手动出口代理，使用进程级 `USE_PROXY` / `PROXY_URL` 环境变量。

## 数据与安全边界

- 搜索、正文读取、引擎状态、Token、设置、历史与审计均调用本地 Fastify API；开发环境由 Next rewrite 提供同源路径。
- React JSX 默认以文本节点呈现搜索结果、日志和正文，不使用 `innerHTML`。
- V1 不展示或实现 Playwright 控件；Bing 的原型界面保留 Auto / Request 选项，实际请求一律使用安全的 Request 模式。
