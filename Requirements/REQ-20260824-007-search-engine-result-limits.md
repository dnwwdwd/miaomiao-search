# REQ-20260824-007 多引擎独立结果数量与分组展示

## 状态

已确认，实施中。

## 目标

每个搜索引擎可以单独配置返回数量，搜索服务按引擎并发请求并同时提供引擎分组结果与兼容的聚合去重结果。首页默认展示分组结果，MCP `search` 保留现有平铺 `results` 字段。

## 已确认规则

- `engine.result_limit` 可空，范围 1–50；为空时使用搜索默认值 `search.defaultLimit`，初始值为 10。
- 调用方 `limit` 改为可选上限；引擎本次有效数量为 `min(limit, result_limit || search.defaultLimit)`，未传调用方上限时使用引擎配置。
- 每个引擎拥有独立缓存键，键包含 query、engine、有效数量和搜索模式。
- 每个引擎先按自身有效数量截取结果，再按 canonical URL 生成聚合去重结果；分组结果保留同 URL 的各引擎版本，聚合结果合并来源标签。
- 单引擎失败保留其他引擎结果；全部失败返回 `ALL_ENGINES_FAILED`。
- 搜索响应增加 `engineResults[]` 和 `resultCount`，继续返回 `results`、`failures`、`cached`、`requestId`。
- 历史快照可包含 `engineResults`，旧快照只包含聚合结果时继续正常读取。
- 首页默认使用引擎配置；首页选择的本次请求上限和 Bing 模式通过 `/api/settings` 持久化，刷新、重新登录或换浏览器后继续使用。请求上限为空时仍表示使用引擎配置，不改变引擎管理页的独立数量，也不限制聚合去重后的总数。

## 影响范围与安全边界

影响引擎管理 API、搜索 API、缓存、历史快照、MCP Tool 和门户首页。保留既有 SSRF、XSS、认证、限流、查询日志和正文抓取边界；不增加 MCP 管理页 Playground。

## 验收矩阵

| 场景 | 验收 |
|---|---|
| 旧引擎记录 | 迁移后 `result_limit` 为空且搜索使用搜索默认值 10 |
| 引擎设置 | GET/PATCH 可读写 1–50，允许 null 清空，非法值拒绝 |
| 多引擎搜索 | 各引擎收到自己的有效数量，受到调用方上限约束 |
| 结果兼容 | `engineResults` 分组存在，`results` 仍为去重聚合结果 |
| 局部失败 | 失败引擎有失败信息，其他分组和聚合结果仍返回 |
| 全部失败 | 返回 `ALL_ENGINES_FAILED` |
| 缓存 | 引擎、数量、模式变化不会命中旧数量缓存 |
| 历史/MCP | 新旧快照可读；MCP 文本 JSON 与结构化响应一致 |
| 首页 | 分组/聚合切换、加载、空结果、局部失败、全部失败和超时状态可用 |
