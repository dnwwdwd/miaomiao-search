# REQ-20260824-002 搜索历史结果与首页体验

## 背景

当前搜索历史只保存关键词、引擎和数量，点击记录无法恢复当次结果，也无法区分“查看旧快照”和“重新获取最新结果”。首页信息层级也偏平，历史入口不够明显。

## 范围

- 持久化搜索结果快照与失败引擎信息。
- 历史弹窗展示记录摘要、引擎选择、结果快照，并支持再次搜索。
- 按 `lazycat_search_portal.html` 的已有视觉语言优化 Next.js 首页布局，不改变搜索 API、SSRF 防护或引擎运行模型。

## 数据流

- 写入：`SearchService.search` 在 Web 搜索成功/部分成功后调用 `AuditService.saveHistory`。
- 持久化：SQLite `search_history.result_snapshot`，JSON 格式 `{ results, failures }`。
- 读取：`GET /api/history` 返回 `snapshot`；旧记录 `snapshot = null`。
- 刷新：历史详情的“再次搜索”复用当前搜索 API，并以当前仍启用的保存引擎为准。
- 清理：既有清空历史与保留天数策略继续生效。

## 验收矩阵

| 场景 | 预期 |
|---|---|
| 新搜索成功 | 历史记录可查看标题、URL、摘要和来源引擎 |
| 部分引擎失败 | 结果可查看，并显示失败引擎与错误信息 |
| 旧历史无快照 | 显示空状态，不阻塞再次搜索 |
| 已保存引擎被停用 | 再次搜索给出明确提示，不发出空引擎请求 |
| 清空历史 | 列表与详情入口同步消失 |
| 旧数据库 | 自动增量迁移，已有字段和记录保留 |
