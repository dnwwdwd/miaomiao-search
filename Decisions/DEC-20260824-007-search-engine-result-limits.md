# DEC-20260824-007 多引擎独立结果数量与分组展示

## 决策

采用“引擎独立配置 + 调用方临时上限”的双层限制模型。数据库使用可空 `engine.result_limit`，空值不写入重复配置，而是动态读取 `search.defaultLimit`。服务端拆分为每引擎一次上游调用，并由 `engine.concurrency` 控制并发 worker 数。

响应保持双形态：`engineResults[]` 是按引擎的真实结果和缓存/失败状态，`results` 是按 canonical URL 去重并合并来源后的兼容平铺结果。这样首页可以直接呈现分组，已有 MCP 客户端无需迁移即可继续读取 `results`。

首页的“每引擎本次上限”和 Bing 搜索模式作为管理员首页偏好写入现有 `setting` 表，并通过 `/api/settings` 读写；首页选择“使用引擎默认值”时保存空值。该偏好只影响 Web 首页的默认请求参数，不覆盖引擎管理配置，也不改变 MCP 调用方的默认行为。

## 取舍与约束

- 分组结果先截取，聚合只做跨引擎去重，避免某一个引擎的重复 URL 挤占其他引擎的独立配额。
- 每个引擎单独缓存，数量配置和搜索模式进入缓存键，避免配置变化复用旧数量。
- 引擎来源由服务端以已选引擎覆盖上游返回值，防止上游缺少或伪造来源。
- 不新增依赖，不改变 Token Secret 持久化方式，不放宽 SSRF 校验。

## 回滚

代码回滚前先保留 `0002_engine_result_limit` 迁移记录；旧版本服务忽略新增列即可启动，旧客户端继续读取平铺 `results`。不得删除已应用迁移或重置用户数据库。
